# QA 页面改造 — 设计文档

> 日期：2026-07-19
> 状态：设计稿

## 背景

当前 QA 页面采用左右分栏对话模式（左历史列表 + 右聊天流），体验上更像即时通讯而非知识问答。用户期望的是 Stack Overflow / 知乎风格的知识条目列表，而非 ChatGPT 风格的对话流。

## 目标

1. QA 页面从「对话模式」改为「问答条目模式」
2. 支持追问（多轮）归入父条目，折叠展示
3. 新问题和追问的操作入口清晰

## 交互规则

| 操作 | 结果 |
|------|------|
| 页面加载 | 展示全部 QA 条目列表（按时间倒序） |
| 点击 `[+ 新问题]` | 创建空白条目，输入框清空，聚焦 |
| 底部输入框直接打字回车 | 归为当前展开条目的追问 |
| 输入 `/new 问题内容` | 创建新条目，标题=问题内容 |
| 点击 `[☰ 历史]` | 展开/收起侧边历史列表 |
| 点击某条目 | 展开该条目详情 + 追问 |
| 追问 | 折叠在条目下方，箭头展开 |

## 条目卡片设计

每条 QA 条目包含：

```
📌 问题标题                    🔥 访问计数  📅 日期
─────────────────────────────────────────────
答案内容（markdown 渲染）
📎 引用: auth.py:42  middleware.py:15

┌─ ▶ 2 条追问 ────────────────────────────┐
│  追问1  📎 file.ts:10                    │
│  追问2                                  │
└──────────────────────────────────────────┘
```

## 追问输入框

固定在当前展开条目的底部：

```
┌──────────────────────────────────────────────┐
│  追问此问题...  (/new 创建新问题)    [发送]    │
└──────────────────────────────────────────────┘
```

## 技术改动

- QAPage.tsx 重构：移除左右分栏，改为条目列表
- 追问数据结构：在现有 qa_entries 表中用 `parent_qid` 字段（已存在）关联
- 追问展开/收起：前端 state 控制
- `/new` 命令解析：输入框检测 `/new` 前缀
