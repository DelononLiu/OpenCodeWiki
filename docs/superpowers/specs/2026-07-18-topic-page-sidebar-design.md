# OpenCodeWiki UI 全面升级 Design Spec

## 系统定位

**团队知识平台**——基于代码和问答的自进化 QA 系统。人人可参与，管理员拥有最终审核权限。

### 核心闭环

```
代码库 ──→ QA 问答 ──→ Topic 聚合 ──→ Wiki 固化
  ↑            ↑           ↑            ↑
 提交建议     提问+关联    编辑提炼稿    建议修改
 人人可做     人人可做    人人可做      人人可做
                              ↓
                         审核台（管理员最终批准）
```

### 权限模型

| 动作 | 普通成员 | 管理员 |
|------|---------|--------|
| 浏览所有内容 | ✅ | ✅ |
| 提问 | ✅ | ✅ |
| 提交代码库建议 | ✅ "提交" | ✅ 直接接入 + 审核提交 |
| 关联 QA → topic | ✅ | ✅ |
| 编辑 topic 提炼稿 | ✅ "建议修改" | ✅ 直接编辑 |
| 建议沉淀为 wiki | ✅ "建议沉淀" | ✅ 直接沉淀 |
| 审核别人改动 | ✅ 可查看待审列表 | ✅ 可执行批准/拒绝 |
| 最终发布/合并 | ❌ | ✅ |

## 1. Header（所有页面统一）

```
[W OpenCodeWiki ...]              [首页] [Wiki] [问答] [👤 long2015 ▾]
```

- 每个页面显示三个导航按钮，不区分当前页
- 用户下拉分为两级：

**管理员：**
```
┌──────────────┐
│ 审核台         │  → /admin
│ ─────────    │
│ 个人设置       │  → /settings
│ 退出登录       │
└──────────────┘
```

**普通成员：**
```
┌──────────────┐
│ 个人设置       │  → /settings
│ 退出登录       │
└──────────────┘
```

- 角色判定：初期config白名单，后续OAuth/SSO

## 4. 仓库 Wiki `/:repo`

### wiki 模式

```
/:repo#overview
┌─ Header ──────────────────────────────────────────────┐
├─ 左侧栏 ──┬─ 主内容区 ────────┬─ 右侧栏 ──────────────┤
│ 物理视角   │ [markdown 内容]   │ 📑 文章大纲            │
│ 📄 概览    │                   │  ## 设计哲学           │
│ 📖 双路..  │                   │  ## 核心模块           │
│            │                   │    ### 双路路由        │
│ 逻辑视角   │                   │  ## 部署配置           │
│ #qa-engine │                   │                       │
│ #concurr.. │                   │                       │
└────────────┴───────────────────┴───────────────────────┘
```

### topic 模式

```
/:repo#qa-engine
┌─ Header ──────────────────────────────────────────────┐
├─ 左侧栏 ──┬─ 主内容区 ────────┬─ 右侧栏 ──────────────┤
│ 物理视角   │ # 双路路由实践     │ 📎 关联 QA            │
│ 📄 概览    │                    │ #Q103 LSH 卡顿...     │
│ 📖 双路..  │ 提炼稿 markdown   │ #Q107 双路分流...     │
│            │                    │                       │
│ 逻辑视角   │ [建议修改] 按钮     │ 📖 关联页面            │
│ #qa-engine │                    │ 02-qa-engine          │
│ #concurr.. │                    │                       │
└────────────┴────────────────────┴──────────────────────┘
```

### 右侧栏

**wiki模式：TOC**
- 从 markdown HTML 提取 h1~h3，DOM解析
- 点击跳转，IntersectionObserver 滚动高亮
- 缩进：h1 0, h2 +8px, h3 +16px

**topic模式：关联内容**
- 关联QA列表（最多20条），点击跳转QA页
- 关联 Wiki 页面（从 topic.wiki_module + draft markdown 提取）

### 权限

- 普通成员点击 topic 页的"建议修改" → 编辑提炼稿 → 提交审核
- 管理员可直接编辑并保存

```
┌─ Header ───────────────────────────────────────────────┐
├─ 左侧栏 (w-72) ──┬─ 主内容区 ──────────────────────────┤
│ 🔍 搜索QA...      │                                      │
│                   │  QA详情 / 提问界面                    │
│ [全部] [domain]   │                                      │
│                   │                                      │
│ 今天              │                                      │
│  Redis连接池...    │                                      │
│   #103 #concurrency│                                     │
│                   │                                      │
│ 三天内              │                                      │
│  双路分流...       │                                      │
│   #107 #qa-engine  │                                      │
│                   │                                      │
│ 本周              │                                      │
│  ...              │                                      │
│                   │                                      │
│ [+ 新建提问]       │                                      │
├───────────────────┴──────────────────────────────────────┤
│  [#context-tag] 提问输入框                      [→]      │
└──────────────────────────────────────────────────────────┘
```

### 左侧栏

- 日期分组：今天 / 三天内 / 本周 / 本月 / 更早
- 每行：标题 + #qid(小号灰色) + #topic(小号灰色)
- domain 过滤标签行
- 不显示 QA 状态（"已沉淀"/"聚合中"），普通用户不需要看
- 空态："暂无 QA 记录，从首页或 Wiki 页底部提问开始"

### 主内容区

- 点击左侧QA条目 → 显示完整QA详情（答案markdown、来源引用）
- 点击"+ 新建提问" → 提问模式（SSE流式对话）
- QA详情页可操作：关联/解绑topic

## 6. 审核台 `/admin`

```
┌─ Header ───────────────────────────────────────────────┐
├─ 左侧栏 ──┬─ 主内容区 ─────────────────────────────────┤
│ 审核队列    │                                             │
│            │  [默认视图: 待审核列表]                       │
│ ⏳ QA校准  │  ┌─ QA 校准 ──────────────────────────┐    │
│   (3)     │  │ #Qxxx question         [校准] [跳过] │    │
│            │  └────────────────────────────────────┘    │
│ 📝 Topic建议│                                             │
│   (2)     │  ┌─ Topic 发布建议 ────────────────────┐    │
│            │  │ #qa-engine 成员建议沉淀              │    │
│ 📖 Wiki变动 │  │ [查看] [批准] [拒绝]               │    │
│   (1)     │  └────────────────────────────────────┘    │
│            │                                             │
│ 🗃️ 代码库   │  ┌─ 代码库接入建议 ────────────────┐      │
│   (1)     │  │ docs-main 成员提交接入              │      │
│            │  │ [批准] [拒绝]                      │      │
│            │  └────────────────────────────────────┘      │
│            │                                             │
│            │  管理员可执行批准/拒绝操作                      │
│            │  普通成员只能查看，按钮置灰                      │
└────────────┴─────────────────────────────────────────────┘
```

- **所有人可见**，但执行操作的按钮仅管理员可用
- 左侧栏四个队列：QA校准、Topic建议、Wiki变动、代码库提交
- 每个队列显示badge计数
- 普通成员看到的是"公众监督视图"：可以看到待审内容但无法操作

## 术语重命名：promote → publish

| 位置 | 旧 | 新 |
|------|-----|-----|
| 数据库 `topics.status` | `'promoted'` | `'published'` |
| 数据库 `topics.promoted_at` | `promoted_at` | `published_at` |
| 数据库 CHECK 约束 | `CHECK(status IN ('pool', 'promoted'))` | `CHECK(status IN ('pool', 'published'))` |
| Python `store_topics.promote()` | `promote()` | `publish()` |
| API 路由 | `POST /api/topics/{slug}/promote` | `POST /api/topics/{slug}/publish` |
| 前端 `api/client.ts` | `promoteTopic()` | `publishTopic()` |
| 按钮文案 | "晋升到 Wiki" | "沉淀为 Wiki" |
| 状态标签文案 | "已固化" | "已沉淀" |
| TypeScript `Topic.status` | `'pool' \| 'promoted'` | `'pool' \| 'published'` |
| TypeScript `Topic` 字段 | `promoted_at` | `published_at` |

## Spec 自检

- **占位符**：无
- **一致性**：所有页面遵循统一 Header、权限口径、视觉风格
- **范围**：本 spec 涵盖页面结构和权限逻辑；后端"提交审核"流程和通知机制留在后续 spec
- **歧义**：管理员/普通成员初期由 config 白名单判定，后续接入认证系统
