# 调研 06 — WeKnora 功能借鉴分析

> 日期：2026-07-18
> 来源：WeKnora v0.7.0（Tencent 开源，MIT License）

## 背景

WeKnora 是腾讯开源的 LLM 知识管理框架，核心能力为 RAG + ReAct Agent + Wiki Mode。与 OpenCodeWiki 定位相近但功能更丰富。本次调研提取对 OpenCodeWiki 可借鉴的功能点。

## Top 5 可借鉴功能

### 1. Agent Skills（渐进式加载）

三级加载模型：

| 级别 | 加载时机 | 内容 | Token 成本 |
|------|---------|------|-----------|
| Level 1 | 始终在 system prompt | skill 名称 + 一行描述 | ~100 tokens |
| Level 2 | agent 调用 `read_skill` 工具 | 完整 SKILL.md 指令 | 按需 |
| Level 3 | 按需执行 | shell/Python 脚本（subprocess） | 执行时 |

**价值**：零代码扩展 Agent 能力。团队可为常见问题编写 Markdown skill。
**复杂度**：低——Skill 注册表 + `read_skill`/`execute_skill` 工具。
**参考实现**：`internal/agent/skills/skill.go`

### 2. 建议问题 + 追问

LLM 分析代码后自动生成 5-10 个建议问题，展示在首页和 QAPage。
**价值**：提升用户发现效率，增加核心闭环的循环次数。
**复杂度**：低——一次 LLM 调用 + 存储 + 前端 Chip 组件。

### 3. 轻量知识图谱增强检索

WeKnora 使用 Neo4j 做 GraphRAG。OpenCodeWiki 可借鉴思路但不引入 Neo4j——利用已有 `code_callers`/`code_callees` 工具输出的调用链，结构化为 Agent 可遍历的图。

**价值**：提升多跳代码问题的检索准确率。
**复杂度**：中——需要结构化调用链数据 + Agent 图查询工具。
**注意**：不引入 Neo4j，用已有 AST 分析数据即可。

### 4. Wiki 自动生成管线

分 5 阶段执行：

```
分类规划 → 总结生成 → 实体提取 → 概念提取 → 自动链接
```

每阶段独立，失败不回滚已完成的阶段。
**价值**：提升 Wiki 内容质量和覆盖度，增强检索源。
**复杂度**：中——需要多阶段编排 + 任务状态管理。
**参考**：`internal/agent/wiki` 相关代码。

### 5. 引用弹窗 + RAG 进度展示

SSE 流增加 pipeline stage 事件，前端展示检索→重排序→生成的进度。引用可点击弹出来源。
**价值**：增强用户对回答的信任感。
**复杂度**：低——SSE 扩展 + 前端 Popover 组件。

## 针对当前核心闭环 + QA 准确度的优先级

当前核心闭环：**QA → Topic → Wiki**
QA 准确度 = Agent 检索 + 推理的质量。

| 排名 | 功能 | 影响 QA 准确度 | 实现复杂度 | 理由 |
|------|------|---------------|-----------|------|
| 🥇 | **轻量知识图谱** | 直接 | 中 | 改善多跳代码问题检索，直接提升回答质量 |
| 🥈 | **Wiki 自动生成管线** | 间接 | 中 | 更好的 Wiki 内容 = 更好的检索源 |
| 🥉 | **Agent Skills** | 间接 | 中 | Skill 可为特定领域提供更精确的指导 |
| 4 | **建议问题** | 不提升 | 低 | 改善发现和交互，不提升准确度 |
| 5 | **引用弹窗** | 不提升 | 低 | 改善信任感，不提升准确度 |

**结论**：优先实现 **知识图谱增强检索** 和 **Wiki 自动生成管线**，直接作用于 QA 准确度和内容闭环质量。

## 不借鉴的功能（红牌）

| WeKnora 做法 | 舍弃理由 |
|-------------|---------|
| 9 个 IM 集成 | 偏离核心闭环，维护成本高 |
| 8 种向量数据库 + 8 种存储后端 | 过早抽象，SQLite 够用 |
| Go 协程池 + 任务队列 + 模型级并发 | 单进程 Python 不需要 |
| RBAC 权限矩阵 | 当前单人场景不需要 |
| YAML 声明式模型配置 | Python 用 Pydantic 更安全 |
| Neo4j 硬依赖 | 用已有 AST 调用链数据代替 |
